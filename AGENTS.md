Keep the codebase organized and readable by humans.

## General

- Avoid adding comments; strive for lucid code instead.

## Commits

- Add scopes to [.commitlintrc](./.commitlintrc) as features grow; use `general` until then.
- Suffix `!` after scope to indicate breaking changes; e.g. `feat(general)!: encrypt storage`.

## Components

- Use Angular CLI generator to generate components.
- Log component initialization.
- Use the component selector (without the `jet-` prefix) as its Transloco `prefix`.

## Dependencies

- Run `reinstall-dependencies` to update all dependencies.
- Update `x:*` scripts whenever adding or removing packages.

## Icons

- Use `-filled` variants of Material Symbols.
- Register all icons used by a component using [addSvgIconLiteral](./src/app/utilities/add-svg-icon-literal.utility.ts).

## Names

- Avoid abbreviations.
- Avoid synonyms to reduce cognitive load; e.g. use one of (authenticate, sign-in, login, etc.), use one of (bag, basket, cart, etc.).

## Scripts

- Keep scripts organized alphabetically, keeping those generated by Angular CLI at the top.

## Styles

- Avoid adding CSS. Use Angular Material components as-is.
- Avoid adding unnecessary CSS.
- Prefer Tailwind classes for local, component-specific styles. Use the component's `styles` property for complex classes.
- Use [material-theme.scss](./src/material-theme.scss) for Angular Material overrides.
- Use [styles.css](./src/styles.css) for reusable styles.

## Security

- Update CSP in [angular.json](./angular.json) and [vercel.json](./vercel.json) as you go; keep domains sorted.

## Services

- Use Angular CLI generator to generate services; then add a mock.
- Log service initialization.
- Avoid using Transloco in root-level services; the translation file may not be available at the time of service initialization.
