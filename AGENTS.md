Keep the codebase organized and readable by humans.

## General

- Avoid adding comments; strive for lucid code instead.
- Add `inject` at the top, sorted in the order of import.
- Initialize class properties inside the constructor, in the order of declaration.

## Commits

- Follow [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/).
- Add scopes to [.commitlintrc](./.commitlintrc) as features grow; use `general` until then.

## Components

- Use Angular CLI generator to generate components.
- Log component initialization.
- Use the component selector (without the `jet-` prefix) as its Transloco `prefix`.

## Dependencies

- Run `reinstall-dependencies` to update all dependencies; update the four child scripts whenever adding or removing packages.

## Forms

- Add clear button on inputs, selects and textareas.
- Add visibility toggle on password inputs.
- Add `enterkeyhint` and `inputmode` attributes on inputs and textareas.
- Implement [hasUnsavedChangesGuard](./src/app/guards/has-unsaved-changes/has-unsaved-changes.guard.ts) on forms.

## Icons

- Use `-filled` variants of Material Symbols.
- Register all icons used by a component using [addSvgIcons](./src/app/utilities/add-svg-icons.utility.ts).

## Names

- Avoid abbreviations.
- Avoid synonyms to reduce cognitive load; e.g. use one of (authenticate, sign-in, login, etc.), use one of (bag, basket, cart, etc.).
- Component names should be suffixed with the UI component it builds upon; e.g. `FaqExpansionPanel`, `OrdersTable`, `ProfileCard`. For page components, suffix `page`.
- Name variables the same as what they `inject` camel-cased.
- Suffix units where applicable; e.g. `discountUsd`, `TIMEOUT_MS`, etc.

## Routes

- Update [sitemap-main.xml](./public/sitemaps/sitemap-main.xml) when adding a route.
- Add path to [nav-items.constant.ts](./src/app/constants/nav-items.constant.ts).
- Set prerendering strategy in [app.routes.server.ts](./src/app/app.routes.server.ts).

## Scripts

- Keep scripts sorted, keeping those generated by Angular CLI at the top.

## Styles

- Avoid adding CSS. Use Angular Material components as-is.
- Avoid adding unnecessary CSS.
- Prefer Tailwind classes for local, component-specific styles. Use the component's `styles` property for complex classes.
- Use [material-theme.scss](./src/material-theme.scss) for Angular Material overrides.
- Use [styles.css](./src/styles.css) for reusable styles.

## Security

- Update CSP in [angular.json](./angular.json) and [vercel.json](./vercel.json) as you go; keep domains sorted.

## Services

- Use Angular CLI generator to generate services; then add a mock.
- Log service initialization.
- Avoid using Transloco in root-level services; the translation file may not be available at the time of service initialization.
